# Ясномера

Ясномера — независимый русскоязычный образовательный сервис «Понятные расчёты для финансовых решений». В сервисе нет заявок, лидогенерации и предложений банков. [Production](https://yasnomera.ru/) · [GitHub](https://github.com/Porfhub/my_calculator)

## Контекст задачи

- При работе с калькулятором прочитай [его паспорт](docs/pages/README.md), применимые общие правила, затем актуальный исходник и профильные тесты. Для QA начни со ссылок в паспорте.
- Для знакомства с проектом используй [обзор](docs/project-context/PROJECT_OVERVIEW.md), для статуса [срез main и релизов](docs/project-context/00_PROJECT_MASTER_STATUS.md), для продуктовых решений [журнал](docs/project-context/01_DECISION_LOG.md).
- Для инфраструктуры, данных и общих контрактов начни с [технической передачи](docs/project-context/02_TECHNICAL_HANDOFF.md). Работа с зеркалом описана в [инструкции Windows](docs/project-context/03_CONTEXT_MIRROR_RUNBOOK.md).

## Контракты

- Согласуй изменение финансовой модели заранее. Различай ввод, официальные факты и модельные допущения. Сохраняй числовые эталоны, provenance, validators и freshness policies. Ошибку или недоступный официальный источник показывай явно, без синтетической подстановки.
- Ставь главный результат раньше методологии. Проверяй mobile-first композицию, светлую и графитовую темы, ошибки, клавиатуру, фокус и доступность. Используй общие компоненты, когда их контракт подходит странице.
- Сохраняй семантику событий и исключай ложные конверсии. Передача финансового ввода требует обоснования и согласования. Проверяй Вебвизор, URL и PNG/share. Формулируй свойства приватности в пределах проверенных механизмов.

## Разработка и сопровождение

- Работай от актуального main в согласованных границах. Используй существующую архитектуру, добавляй релевантные регрессионные тесты и запускай применимые проверки. Для пользовательских изменений выполняй browser QA.
- В каждом PR, меняющем финансовую модель, интерфейс, ввод, дефолты, аналитику, PNG/share или источники данных калькулятора, проверь его паспорт, обнови затронутые разделы, зафиксируй решения и ограничения, добавь необходимые числовые эталоны и включи Markdown в тот же PR. Это также относится к выходам, ошибкам и приватности. Если контракт страницы сохраняется, достаточно проверить актуальность паспорта.
- Обновляй общие документы при значимых изменениях. Решение внеси в журнал, архитектуру и общие контракты в техническую передачу, подтверждённые изменения статуса в master status. Различай предложение, реализацию в ветке, открытый PR, merge, успешный deploy и проверку production. Используй код, тест, PR, workflow или подтверждение владельца как опору.
- Готовь один ограниченный PR. Merge требует отдельного решения владельца, ручной production deploy — прямого разрешения. GitHub main является источником документации. Drive и ChatGPT Project используют его копии.
