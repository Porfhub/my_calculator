# P0.3 — инженерная спецификация источника данных об инфляции

## Статус документа

- Тип изменения: исправление качества и происхождения данных P0.3.
- Эта ветка содержит только спецификацию. Реализация и изменения runtime-кода в неё не входят.
- Цель будущей реализации: исключить ручные, синтетические и молча подставляемые значения инфляции; использовать воспроизводимый официальный ряд и явно сообщать о состоянии данных.

## 1. Файлы будущей реализации

Потребуется изменить:

- `update_inflation.js` — заменить встроенный архив и чтение текущего показателя ЦБ на загрузку, фильтрацию, проверку и сохранение официального ряда Росстата; реализовать состояния `ok`, `stale`, `unavailable`.
- `inflation.json` — перейти от плоского объекта `год → процент` к версионированной структуре с данными и metadata.
- `js/api.js` — валидировать новую схему и возвращать потребителям данные вместе со статусом, а не неразличимые `null` или произвольный объект.
- `inflation-shredder.html` — читать массив `annual`, прекратить считать отсутствующий год нулевой инфляцией и показать состояние источника.
- `millionaire.html` — считать среднюю инфляцию только по валидным официальным годовым наблюдениям и убрать молчаливый числовой fallback.
- `financial-freedom.html` — аналогично перейти на валидированный ряд и явное состояние недоступности.
- `genetic-wealth.html` — аналогично перейти на валидированный ряд и явное состояние недоступности.
- `sw.js` — поднять версию кэша при смене схемы, чтобы старый плоский `inflation.json` не попадал новым потребителям из offline-кэша.
- `.github/workflows/rates.yml` — уточнить название шага/commit message и проверку результата обновления инфляции; расписание и общая схема workflow остаются прежними.
- `TECH_PASSPORT.md` — заменить устаревшее описание источника и fallback на фактический контракт Росстата и правила статусов.

Новые runtime-файлы и новый backend не требуются. Если официальный экспорт будет выбран в XLSX, отдельно потребуется добавить только минимальную build-time зависимость для безопасного чтения XLSX в `package.json` и lock-файл. Предпочтительный транспорт — официальный CSV/машиночитаемый экспорт ЕМИСС, чтобы не вводить эту зависимость.

## 2. Какие данные используются сейчас

Текущий `update_inflation.js`:

- содержит вручную записанные годовые проценты за 2000–2024 годы;
- отдельно присваивает 2025 году значение `6.8`;
- запрашивает `https://www.cbr.ru/scripts/xml_main_info.asp` и регулярным выражением извлекает блок `<inflation>`;
- при успешном разборе заменяет только один год значением из ответа;
- при любой ошибке всё равно перезаписывает `inflation.json` встроенными значениями;
- не сохраняет источник, дату публикации, момент получения, актуальность и результат проверки.

Текущий `inflation.json` — плоский объект вида:

```json
{
  "2000": 20.2,
  "2001": 18.6,
  "2024": 8.5,
  "2025": 6.8
}
```

Потребители интерпретируют его по-разному:

- `inflation-shredder.html` обращается к значениям по ключу года и заменяет отсутствующий год на `0`;
- `millionaire.html`, `financial-freedom.html` и `genetic-wealth.html` берут последние 15 значений через `Object.values(...)` и считают геометрическое среднее;
- при ошибках отдельные калькуляторы используют встроенные значения `7.8%` или `8%` без указания пользователю, что официальный ряд недоступен;
- в `inflation-shredder.html` присутствуют вручную написанные тексты с конкретными годовыми значениями;
- service worker может отдать ранее закэшированную старую форму JSON.

## 3. Почему текущая реализация неправильна

### Несогласованное определение показателя

Запрашиваемый у Банка России текущий показатель смешан с архивом календарных годовых значений. Для годового ряда необходимо одно определение для всех строк: ИПЦ по Российской Федерации, все товары и услуги, декабрь к декабрю предыдущего года. Текущее решение не фиксирует ни это определение, ни параметры выборки.

### Значения не воспроизводимы

Встроенный массив не связан с конкретным официальным набором данных. Невозможно проверить, из какого релиза взято каждое число, использовалось ли округление и были ли учтены последующие официальные уточнения.

### Есть фактические расхождения

В проекте указано `8.5%` за 2024 год и `6.8%` за 2025 год. В официальной публикации Росстата индекс декабря 2025 года к декабрю 2024 года равен `105.59%`, а декабря 2024 года к декабрю 2023 года — `109.52%`. При выбранном определении это соответствует инфляции `5.59%` и `9.52%` соответственно, до каких-либо UI-округлений.

### Ошибка маскируется как успех

Сбой сети или парсинга приводит к записи тех же встроенных чисел. JSON не позволяет отличить свежие официальные данные от fallback. Дополнительно страницы подставляют `0`, `7.8%` или `8%`, поэтому пользователь получает расчет с выдуманным входным параметром вместо сообщения об ошибке.

### Парсинг недостаточно надежен

XML разбирается регулярными выражениями. Нормализация числа удаляет все символы, кроме цифр и разделителей, поэтому, например, отрицательный знак был бы потерян. Не проверяются полнота ряда, уникальность годов, единицы измерения и нужный срез показателя.

### Схема не расширяема безопасно

В плоский объект нельзя добавить metadata без риска: текущие вызовы `Object.values(...)` примут объект metadata за значение ряда. Смена схемы должна быть атомарной для генератора, API-обертки, всех потребителей и кэша.

## 4. Официальный источник

Источник истины — официальный индекс потребительских цен Росстата:

- набор: ИПЦ на товары и услуги;
- территория: Российская Федерация;
- охват: все товары и услуги;
- периодичность исходного ряда: месяц;
- показатель для годовой строки: декабрь отчетного года к декабрю предыдущего года, в процентах;
- производное значение для интерфейса: `inflation_percent = cpi_index - 100`.

Канонические ссылки:

- [Росстат — «Цены, инфляция»](https://rosstat.gov.ru/statistics/price) — официальная страница набора и публикаций;
- [Росстат — ответы по методологии ИПЦ](https://rosstat.gov.ru/folder/165737) — описание показателя, сроков публикации и официальных способов получения;
- [ЕМИСС — показатель 31074](https://www.fedstat.ru/indicator/31074) — официальный машиночитаемый ряд;
- идентификатор показателя на Витрине данных Росстата: `11521100300010200001`.

Загрузчик должен получать официальный машиночитаемый экспорт показателя, а не извлекать числа из новостного текста или неофициального сайта. В metadata записываются и стабильная страница показателя, и точный URL фактически загруженного экспорта.

До реализации необходимо подтвердить стабильный официальный URL/формат экспорта в среде GitHub Actions. Если ЕМИСС не предоставляет стабильный CSV для автоматической загрузки, допустим официальный XLSX Росстата, опубликованный на странице «Цены, инфляция». Переключение между транспортами не меняет определение ряда и требования к проверке.

Текущий незавершенный год не включается по промежуточному месяцу и не прогнозируется. Новая годовая строка появляется только после официальной публикации показателя за декабрь.

## 5. Целевая структура `inflation.json`

Предлагаемая схема версии 2:

```json
{
  "metadata": {
    "schema_version": 2,
    "status": "ok",
    "source_name": "Росстат / ЕМИСС",
    "source_url": "https://www.fedstat.ru/indicator/31074",
    "source_landing_url": "https://rosstat.gov.ru/statistics/price",
    "source_export_url": "https://example.invalid/exact-official-export",
    "source_checksum_sha256": "<sha256 загруженного официального файла>",
    "indicator_id": "31074",
    "showcase_indicator_id": "11521100300010200001",
    "indicator_name": "Индекс потребительских цен на товары и услуги",
    "geography": "Российская Федерация",
    "coverage": "Все товары и услуги",
    "measure": "декабрь к декабрю предыдущего года",
    "unit": "percent",
    "frequency": "annual",
    "data_through": 2025,
    "source_published_at": "2026-01-16",
    "last_successful_fetch_at": "2026-01-16T12:00:00Z",
    "last_attempt_at": "2026-01-16T12:00:00Z",
    "status_reason": null
  },
  "annual": [
    {
      "year": 2000,
      "cpi_index": 120.2,
      "inflation_percent": 20.2
    },
    {
      "year": 2025,
      "cpi_index": 105.59,
      "inflation_percent": 5.59
    }
  ]
}
```

`example.invalid` в примере намеренно не является рабочим адресом. В реальном файле это поле обязано содержать точный официальный URL фактически полученного экспорта.

Массив `annual` выбран вместо динамических ключей года, потому что он:

- отделяет наблюдения от metadata;
- задает явные типы полей;
- позволяет проверить сортировку и дубликаты;
- хранит исходный индекс и вычисленную из него инфляцию для аудита;
- не зависит от порядка свойств JSON.

Правила данных:

- записи отсортированы по `year` по возрастанию;
- каждый год встречается ровно один раз;
- `cpi_index` хранится с официальной точностью;
- `inflation_percent` равен `cpi_index - 100`, без округления в слое хранения;
- округление для подписи выполняется только интерфейсом;
- в `annual` находятся только завершенные и прошедшие проверку календарные годы;
- неизвестные значения не представляются нулем, `null` внутри записи или прогнозом.

## 6. Metadata

Обязательные поля:

| Поле | Назначение |
| --- | --- |
| `schema_version` | Версия контракта JSON; первоначально `2`. |
| `status` | Одно из `ok`, `stale`, `unavailable`. |
| `source_name` | Человекочитаемое имя официального поставщика. |
| `source_url` | Стабильная официальная страница показателя. |
| `source_landing_url` | Официальная страница Росстата с набором/публикациями. |
| `source_export_url` | Точный официальный ресурс, загруженный при последнем успехе. |
| `source_checksum_sha256` | Контрольная сумма успешно проверенного исходного файла. |
| `indicator_id` | Идентификатор показателя ЕМИСС. |
| `showcase_indicator_id` | Идентификатор на Витрине данных Росстата. |
| `indicator_name` | Официальное название выбранного показателя. |
| `geography` | Зафиксированный территориальный срез. |
| `coverage` | Зафиксированный товарный срез. |
| `measure` | Зафиксированное отношение периодов. |
| `unit` | Единица сохраненных величин: `percent`. |
| `frequency` | Частота публикуемого приложением ряда: `annual`. |
| `data_through` | Последний завершенный год в `annual`; `null`, если данных нет. |
| `source_published_at` | Дата публикации/обновления исходного набора, если она предоставлена источником. |
| `last_successful_fetch_at` | UTC-время последней успешной загрузки и проверки; `null`, если ее не было. |
| `last_attempt_at` | UTC-время последней попытки обновления. |
| `status_reason` | `null` при `ok`, иначе стабильный машинный код причины. |

Допустимые коды `status_reason` должны быть ограничены известным набором, например: `fetch_failed`, `timeout`, `source_format_changed`, `validation_failed`, `no_saved_dataset`. Технические подробности ошибки следует писать в лог workflow, но не включать потенциально чувствительные тексты исключений в публичный JSON.

## 7. Сценарии состояний

### `ok`

Условия:

- официальный файл получен по HTTPS с обычной проверкой сертификата;
- выбран именно требуемый срез;
- весь ряд прошел структурную и смысловую проверку;
- вычисляемые значения согласованы с индексами.

Поведение:

- `annual` заменяется новым проверенным рядом;
- обновляются URL экспорта, checksum, `data_through`, дата публикации и оба timestamp;
- `status_reason` равен `null`;
- калькуляторы используют ряд и при необходимости показывают источник и год актуальности.

### `stale`

Условия:

- текущая попытка загрузки, парсинга или проверки завершилась ошибкой;
- в `inflation.json` уже есть ранее успешно полученный и валидный набор схемы 2.

Поведение:

- `annual`, `last_successful_fetch_at`, источник успешного экспорта и checksum сохраняются без подмены;
- обновляются `last_attempt_at`, `status` и `status_reason`;
- калькуляторы могут продолжить расчет по сохраненному ряду;
- рядом с результатом показывается, что обновление временно недоступно и данные актуальны по `data_through`;
- никакое ручное значение и никакой прогноз не добавляются.

Legacy JSON без metadata не считается доказанным «последним успешным» набором и не может автоматически стать `stale`, поскольку его происхождение неизвестно.

### `unavailable`

Условия:

- получить и проверить официальный источник не удалось;
- ранее успешно сохраненного набора схемы 2 нет.

Поведение:

- `annual` — пустой массив;
- `data_through`, `source_published_at`, `last_successful_fetch_at`, URL экспорта и checksum — `null`;
- сохраняются постоянные идентификаторы и ссылки официального показателя;
- `last_attempt_at` и `status_reason` описывают попытку;
- расчеты, требующие инфляции, не запускаются с числовым fallback;
- интерфейс показывает «данные временно недоступны» и предлагает повторить позже.

## 8. Риски и меры снижения

| Риск | Мера снижения |
| --- | --- |
| ЕМИСС отвечает `403`, меняет экспорт или недоступен из GitHub Actions | До реализации проверить реальный экспорт из CI; использовать только официальный альтернативный XLSX Росстата; при сбое переходить в `stale`/`unavailable`. |
| Ошибка цепочки TLS-сертификатов в среде | Не отключать проверку TLS; исправить доверенные корневые сертификаты runner либо использовать другой официальный endpoint. |
| Изменение структуры CSV/XLSX, заголовков или объединенных ячеек | Парсить по проверяемым семантическим полям, держать обезличенный fixture формата и падать в безопасный статус при несовпадении. |
| Выбран неправильный срез: месяц к месяцу, регион или товарная группа | Жестко фильтровать территорию, охват и меру; проверять, что после фильтра остается ровно одна строка на год. |
| Промежуточный месяц принят за итог года | Добавлять год только по опубликованному декабрю и проверять период сравнения. |
| Росстат уточнил исторический ряд | Принимать новый полностью валидный официальный ряд, хранить checksum и показывать изменение в git diff. |
| Потеря точности из-за раннего округления | Хранить официальную точность, округлять только при отображении. |
| Старый JSON приходит из service worker | Атомарно обновить потребителей и поднять версию кэша. |
| Один из потребителей продолжает читать плоский объект или использовать fallback | Централизовать валидацию в `fetchInflation()` и провести обязательный поиск по проекту. |
| Ошибка источника перезаписывает хороший ряд пустыми данными | Разрешать замену `annual` только после полной проверки; при ошибке сохранять последний успешный ряд. |
| Ежедневный workflow создает шумные commits только из-за timestamp | Не создавать commit, если значимые данные и статус не изменились; timestamps обновлять по определенному правилу и проверять diff перед commit. |

## 9. Проверка корректности

### Проверка источника и преобразования

- Сверить параметры среза с официальной методологией Росстата.
- Проверить контрольные значения по официальной публикации: индекс `109.52` за декабрь 2024 к декабрю 2023 дает `9.52%`; индекс `105.59` за декабрь 2025 к декабрю 2024 дает `5.59%`.
- Убедиться, что список годов строго возрастает, не содержит дубликатов и неожиданных пропусков в поддерживаемом диапазоне.
- Для каждой строки проверить конечность чисел и равенство `inflation_percent = cpi_index - 100` с допустимой погрешностью представления.
- Проверить, что незавершенный год не добавлен.
- Проверить host, content type, предельный размер ответа и checksum загруженного файла.

### Автоматические сценарии обновления

- Успешный официальный ответ создает `status: ok` и новый валидный ряд.
- HTTP-ошибка, timeout, невалидный формат, неверные измерения, пустой и частичный ряд при наличии сохраненного набора дают `stale` и не меняют `annual`.
- Те же ошибки без сохраненного валидного набора дают `unavailable` и пустой `annual`.
- Legacy плоский JSON не принимается как доверенный fallback.
- Отрицательное значение не теряет знак, если дефляция появится в официальном ряду.

### Проверка потребителей

- Все четыре страницы корректно работают с `ok`.
- При `stale` расчеты используют только сохраненный официальный ряд и показывают предупреждение с `data_through`.
- При `unavailable` страницы не используют `0`, `7.8%`, `8%` или иное число и показывают единый понятный статус.
- Последние 15 наблюдений выбираются после сортировки по `year`, а не по порядку свойств объекта.
- Пропуск обязательного года вызывает ошибку данных, а не нулевую инфляцию.
- После обновления service worker не отдает старую схему из предыдущего кэша.

### Smoke-test и контроль scope

- Запустить updater на успешном fixture и на fixture каждого ошибочного сценария.
- Открыть `inflation-shredder.html`, `millionaire.html`, `financial-freedom.html`, `genetic-wealth.html` и выполнить по одному расчету в `ok`, `stale`, `unavailable`.
- Проверить консоль браузера и workflow на отсутствие ошибок.
- Поиском по проекту исключить: `xml_main_info.asp`, ручные значения `6.8`, `8.5`, fallback `0.078`/`0.08`, `Object.values(inflationData)`, `inflationData[year] || 0` и старые тексты с годовыми процентами.
- Проверить `git diff --name-only` и убедиться, что реализация затрагивает только перечисленные в разделе 1 файлы.

## 10. Что не будет изменяться

- Дизайн, верстка, темы и навигация страниц.
- Математические формулы калькуляторов, кроме замены источника входного параметра и запрета выдуманного fallback.
- Остальные калькуляторы и страницы, не потребляющие `inflation.json`.
- `rates.json`, получение ключевой ставки и другие наборы данных.
- Статическая архитектура приложения: scheduled updater → JSON → браузерные потребители.
- Расписание существующего GitHub Actions workflow, если проверка официального транспорта не выявит технической необходимости его менять.
- Стратегия service worker network-first; меняется только версия кэша и совместимость со схемой.
- Исторические значения вручную, прогнозы, оценки текущего незавершенного года и данные неофициальных поставщиков добавляться не будут.

## Критерии приемки будущей реализации

- Каждое показанное число происходит из зафиксированного официального ряда Росстата и воспроизводимо по metadata.
- Невозможно получить расчет с молча подставленным числом при ошибке источника.
- Состояния `ok`, `stale`, `unavailable` различимы программно и понятны пользователю.
- Последний успешный официальный ряд сохраняется при временной ошибке, но legacy/непроверенные значения не получают статус доверенных.
- Новая схема внедрена атомарно во всех потребителях и кэше.
