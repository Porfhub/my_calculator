# Источники Ясномеры в ChatGPT Project

GitHub main — каноническая версия. В Sources проекта добавь [обзор](PROJECT_OVERVIEW.md), [текущий статус](00_PROJECT_MASTER_STATUS.md) и [индекс](../pages/README.md). Для задачи прикрепи сам паспорт нужной страницы, поскольку ссылка из индекса не передаёт содержимое файла. Для архитектурной задачи добавь [техническую передачу](02_TECHNICAL_HANDOFF.md), для обсуждения решений — [журнал](01_DECISION_LOG.md). При работе со всеми инструментами можно подключить все десять паспортов.

## Обновление

1. На GitHub открой main и проверь последний коммит нужного файла. Дата в master status обозначает проверенный срез, а не возраст всех исходников.
2. Если используешь [зеркало Google Drive](03_CONTEXT_MIRROR_RUNBOOK.md), сравни Git SHA из локального журнала с main и убедись в доступности нужного файла в Drive. При подключённом Drive дай чату доступную ссылку на конкретный файл или выбери его как источник, если интерфейс и права позволяют. Проверь, что чат видит актуальный раздел.
3. Загруженные Markdown являются снимками. При изменении источника удали устаревший экземпляр из Sources и загрузи свежий из main или проверенного зеркала. Не держи две версии одного паспорта. При недоступном Drive используй GitHub.
4. Внутри проекта начни новый чат для отдельной задачи, укажи страницу, результат работы и файл-источник. При сомнении попроси сверить нужный раздел с GitHub. [Официальная инструкция OpenAI по проектам](https://learn.chatgpt.com/docs/projects)

В обычном чате удобно уточнить статус или допущение. Режим «Работа» подходит для аудита живой страницы, сравнения мобильной и настольной композиции, финансовых эталонов и подготовки брифа. Codex реализует согласованный бриф в репозитории и проверяет его через код, тесты и QA.

## Короткие задания

**A. UX-аудит в режиме «Работа»**

> Проведи UX- и финансовый аудит `<страницы>` по обзору, паспорту и актуальному main. Проверь production, desktop и mobile. Дай 2–4 приоритета и дизайн-бриф. Реализацию начнём после согласования.

**B. Реализация в Codex**

> Реализуй согласованное `<изменение>` для `<страницы>`. Используй AGENTS.md, паспорт и main. Сохрани финансовую модель, аналитику и PNG/share. Обнови паспорт, проверь тесты и интерфейс. Один PR без merge.

**C. Проверка PR**

> Сверь PR `<номер>` с паспортом `<страницы>`. Проверь математику, UX, приватность, PNG/share и QA. Укажи блокеры и готовность к merge.
