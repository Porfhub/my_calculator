## Продукт и границы

**Ясномера — «Понятные расчёты для финансовых решений».** Независимый русскоязычный образовательный сервис: ипотека, аренда против покупки, стоимость кредита, накопления, финансовая свобода, инфляция, сравнение дохода, автомобиль против такси, стоимость времени, расходы на ребёнка. Расчёты выполняются в браузере.

Это не банк, брокер, финансовый советник, витрина банковских предложений или лидогенератор. Не возвращать фиктивные заявки, сбор контактов, синтетические «ставки банков» и обещания доходности. Официальный факт, пользовательский ввод и допущение модели должны различаться.

## Production и инфраструктура

Статический сайт из 11 HTML-страниц с общими JS/CSS, JSON и PWA; серверного расчётного backend и сборки frontend нет. Используются Tailwind CDN, Chart.js и html2canvas. Канонический адрес — `https://yasnomera.ru/`.

GitHub хранит исходники и запускает Actions. `.github/workflows/deploy-yandex-object-storage.yml` пакует **ровно 35 разрешённых файлов** из latest main, исключает docs/tests/dev_tools/обновляторы и проверяет содержимое по Git. Публикация — Yandex Object Storage, endpoint `https://storage.yandexcloud.net`, production bucket `s3://yasnomera.ru/`, test bucket `s3://yasnomera-test/`. Секреты: `YC_ACCESS_KEY_ID`, `YC_SECRET_ACCESS_KEY`; их значения в документацию не помещать.

Автодеплой происходит при push в main и после **успешного** `Update Mortgage Rates` на main. `workflow_run` с ошибкой корректно пропускается; 30.10 это подтверждено deployment run #47, [41032098132](https://github.com/Porfhub/my_calculator/actions/runs/41032098132). ## Официальные финансовые данные: инцидент и состояние

Ежедневный `.github/workflows/rates.yml`: cron `0 3 * * *` (06:00 МСК; фактический запуск GitHub может задерживаться), Node 24 → `npm ci --ignore-scripts` → `npm test` → два updater-а → publish gate → проверка изменённых путей → commit/push только `rates.json`, `inflation.json`. Health-шаг информационный и не блокирует безопасный degraded publish.

На базе main:

- `rates.json`: **14%**, действует с **27.07.2026**, fetch **2026-10-07T09:30:04.019Z**. Это проверенное содержимое main/production; старый `ok` уже не проходит текущий hard TTL.
- `inflation.json`: ряд 2000–2025, `stale/timeout`, последний успешный fetch 12.09, попытка 07.10.
- `regions.json`: schema v2, **partial**, публикуются только обеспеченные источником показатели. Legacy `update_regions.js` в ежедневный pipeline не включён.

Причина остановки: тесты читали корневой изменяемый `inflation.json`. После перехода в `stale` они унаследовали этот статус, хотя сценарии требовали `ok`. Ревизия попала под защиту неизменности stale вместо проверки исторического скачка; freshness-сценарий уже имел требуемый stale и не бросал ожидаемую ошибку. Схемы и production-валидатор работали правильно. Предыдущая фиксация только тестовых дат в PR #85 не изолировала статус и payload.

**Исправлено локально, ожидает review/merge:** validator/updater и клиентские inflation/state unit-тесты используют отдельный полный fixture, не зависящий от ежедневных JSON. Добавлены точные границы publication grace/hard TTL и регрессии успешного повторного fetch неизменной ставки / отказа источника после TTL. Схемы, provenance, политика свежести и fail-closed не ослаблены.

Реальный локальный прогон 30.10 на ветке PR:

Локально обновлённые JSON входят в предлагаемый PR, а не в production. Следующий шаг по инциденту — review PR, затем только после решения владельца merge и наблюдение успешного daily updater → safe commit → Yandex workflow. ## Реклама и аналитика

По проектным чатам первый исследовательский цикл **Yandex Direct уже состоялся**. Решено сохранять существующую кампанию/историю и baseline; следующий полноценный платный тест — **после ипотечного редизайна и QA**. По сообщению владельца 30.10 он сейчас не оплачивает рекламу; текущее состояние переключателей, расходов и атрибуции в кабинете в этой задаче не проверялось. Не объявлять кампанию технически остановленной и не придумывать бюджет, CTR, CPA или ID кампании.

Исторические наблюдения Webvisor: пользователи меняли прежде всего цену и взнос; часть не доходила до глубоких разделов; были малоинтерактивные просмотры и активные исследования. Мобильные проблемы ввода/скролла исправлялись в production. Пустой canvas в записи Webvisor сам по себе не доказывает поломку Chart.js.

В коде используется **Yandex Metrika counter `110360838`** с webvisor/clickmap/trackLinks. Ключевая конверсия — **`calculate_success`**: в ипотеке один раз после валидного пользовательского изменения и успешного обновления результата, не на исходном примере/невалидном вводе. Диагностика `mortgage_diagnostic` отправляется как categorical session params, не как conversion goals. `share_click` обозначает начало PNG/share-действия, а не доказанное скачивание. Исторически цели проверялись в production; текущий приём событий кабинетом не проверялся заново.
