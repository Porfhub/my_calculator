# Дизайн-система Ясномеры

[design-system.css](../../css/design-system.css) задаёт общие токены и компоненты. В первом PR файл входит в статический пакет и остаётся без подключений в HTML. Визуальные ориентиры — читаемая навигация и компактная справка [главной](../qa/homepage-redesign/2026-11-02/polish/README.md), а также платёж на первом месте, ясные границы полей и раскрываемые детали [ипотеки](../pages/mortgage.md).

## Подключение

На выбранной странице подключите файл после `css/product-polish.css`. Поставьте `.yn-scope` на ближайший контейнер выбранного блока, затем добавьте классы компонентов на конкретные дочерние элементы. Сам контейнер получает только переменные `--yn-*`. Корневые элементы страницы, расчётные секции и локальная сетка сохраняют свои классы и стили.

```html
<link rel="stylesheet" href="css/design-system.css">

<div class="yn-scope">
    <header class="yn-header">
        <div class="yn-header-inner">
            <a class="yn-brand" href="index.html">
                <img src="yasnomera-mark.svg" alt="" width="32" height="32">
                ЯСНОМЕРА
            </a>
            <nav class="yn-header-nav" aria-label="Основная навигация">
                <a class="yn-link" href="index.html">Все расчёты</a>
            </nav>
            <!-- Сюда переносится существующая кнопка темы. -->
        </div>
    </header>
</div>
```

| Блок | Классы и разметка |
| --- | --- |
| Шапка | `yn-header`, `yn-header-inner`, `yn-brand`, `yn-header-nav`, `yn-link`. Сохраните нужные странице пункты, цели ссылок и переход к основному содержанию. |
| Тема | `yn-theme-toggle` на `button type="button"` с именем «Переключить тему». Перенесите текущие обработчики, ID и SVG. На иконках используйте `yn-theme-icon`, `aria-hidden="true"` и существующий класс `hidden` для управления из `theme.js`. |
| Кнопки | `yn-button` на кнопке действия или ссылке перехода. Добавьте `yn-button--primary` для главного действия. Для недоступного действия используйте нативный `disabled` на кнопке. |
| Поля | `yn-field` на контейнере, `yn-label` на `label`, `yn-input` на текстовом или числовом поле, `select` или `textarea`. Для подсказки и ошибки используйте `yn-hint` и `yn-error`. Свяжите их с полем через `aria-describedby`, укажите `aria-invalid="true"` при ошибке. |
| Методология | `yn-methodology` на `details`, `yn-methodology-summary` на первом дочернем `summary`, `yn-methodology-body` на контейнере текста. Раскрытие работает нативно. |
| Статусы | `yn-status` для нейтрального сообщения, модификаторы `yn-status--success`, `yn-status--warning`, `yn-status--error` для соответствующих состояний. Для изменяемого сообщения уместен `role="status"`, для срочной ошибки — `role="alert"`. |
| Футер | `yn-footer` на `footer`, `yn-footer-inner` на строке с текстом и действиями. Ссылки и кнопки оформляются явными классами. |

## Темы и доступность

Светлая палитра действует в `.yn-scope` по умолчанию. Графитовые цвета включаются существующим `html.dark`. [theme.js](../../js/theme.js) по-прежнему отвечает за выбор, системное предпочтение и сохранение темы. Токены описывают назначение цвета, размер текста, интервалы, скругления, границы, фокус и состояния. Используйте их внутри подключённого блока. Для локального варианта переопределяйте нужный токен на контейнере этого блока.

- Проверяйте обычный текст на контраст от 4,5:1, а границы полей и видимый фокус от 3:1 на фактическом фоне. Состояние передавайте текстом вместе с цветом.
- Сохраняйте нативные элементы и логичный порядок фокуса. Проверяйте Tab, Enter и Space, индикатор фокуса и отсутствие обрезания при узком viewport и увеличении текста. У интерактивных элементов шапки и методологии целевая высота от 44 CSS px.
- Выводите главный ответ перед объяснением. Композиция, акценты, графики и детализация зависят от задачи калькулятора. При переносе методологии сохраняйте источники, допущения, ограничения и связанные с ними правила приватности.

## Финансовые форматы

- Форматируйте вывод через `Intl.NumberFormat('ru-RU')` и используйте существующие помощники страницы, если их точность соответствует паспорту. Например, [formatMoney](../../js/utils.js) показывает целые рубли как `1 234 567 ₽`, дробные значения используют запятую. Для процентов форматтер получает долю (`0.1625` → `16,25 %`). Если модель хранит процентные пункты, преобразуйте единицу только при отображении.
- Сохраняйте неразрывные пробелы внутри суммы и перед единицей измерения, знак отрицательной величины и согласованные разряды. `yn-number` включает табличные цифры для сравнимых значений. Модель, ввод, URL и экспорт продолжают использовать свои контрактные представления. Округление при показе не меняет расчёт.
- Различайте ноль, отсутствие данных и ошибку. Указывайте единицы и период рядом с показателем. Сумма с копейками, точность ставки и склонение срока определяются паспортом страницы.

## Следующие PR

1. В отдельном PR подключите шапку и кнопку темы на согласованных страницах. Для каждой сверяйте ссылки и существующие обработчики. Учитывайте адресные legacy-правила `product-polish.css` для прямых дочерних элементов `.calculator-page` и `#theme-toggle`. Ипотека остаётся защищённым эталоном, её подключение требует отдельного согласования.
2. Отдельным PR подключите методологию на согласованных страницах. Кнопки, поля, статусы и футер применяйте при целевой доработке страницы и проверяйте паспорт в том же PR.
3. При первом подключении согласуйте политику service worker для CSS и проверьте холодный офлайн-запуск. Файл уже внесён в точный allowlist Yandex Cloud и HTTP smoke. Для новых файлов обновляйте точный список, сохраняя проверку количества, хешей и запрет симлинков. [Техническая передача](../project-context/02_TECHNICAL_HANDOFF.md)
