# Действующая ипотека — утверждённая схема

Дата: 02.11.2026. **Статус: одобрено основателем 02.11.2026, реализовано в PR #93; ещё не main/production.** Основатель также подтвердил появление контрольных calculate_success в Метрике. Переключатель/сброс остатка и новая форма объединены в том же PR для одной приёмки/выпуска.

## Подтверждённые проблемы

1. «Осталось платить» и «Уже выплачено» — два редактируемых представления одной зависимости: первоначальный срок × 12 − прошедшие месяцы. Пример 20 лет, осталось 19 лет 8 мес. → прошло 4 месяца. Это не сумма уже уплаченных денег.
2. Изменение remaining/paid не обновляет текущий остаток. В сценарии из примера elapsed стал 4 вместо 36, остаток 7 651 642 сохранился. Будущий расчёт использует эти входы, а историческая оценка смешивает их с теоретическим исходным платежом.
3. Known-payment rate edit и возврат на existing tab перезаписывали реальный остаток скрытыми исходными данными. Это bug; точечный guard исправляется сейчас без изменения движка.
4. История не восстанавливается достоверно по текущему остатку/ставке/платежу. Надписи «реальный прогресс» и «уже выплачено» без оговорок вводят в заблуждение. Пустая history-card в known-payment режиме не помогает сценарию будущих выплат.

## Принятый основной сценарий

Первые общие поля: текущий остаток основного долга из банковского приложения, текущая годовая ставка. Выбор способа ввода — явные сегменты, а не булевый тумблер:

| Режим | Пользователь вводит дополнительно | Рассчитываем |
| --- | --- | --- |
| Знаю платёж (основной) | Обязательный платёж без страховки/доплат | Прогноз срока, будущие проценты и общие выплаты |
| Знаю оставшийся срок | Оставшиеся годы/месяцы из актуального графика | Расчётный обязательный платёж, будущие проценты и выплаты |

Числа результата/ввода явно различаются. При смене режима сохраняются остаток, ставка, страховка и доплаты. Нельзя молча перезаписывать банковский остаток. Новая расчётная модель не нужна: адаптер ввода должен сохранить проверенный simulator и совместимость прежних share URL. Соответствие входов, валидация и инварианты проверяются целевыми UI regression tests, а не только engine parity.

## Сохранить полезные дополнительные функции

- «Не знаю остаток — оценить по исходным условиям» раскрывает первоначальную сумму, ставку, срок и число уже внесённых платежей. Расчётный остаток помечается как оценка без прошлых досрочных/изменений ставки; подстановка в основной сценарий явная.
- Отдельного редактируемого «Уже выплачено» в основной форме нет. При восстановлении исходного графика elapsed — понятный ввод «Сколько ежемесячных платежей уже внесли», остаток срока — read-only следствие.
- История — необязательное раскрытие «Оценка прошлых выплат по исходному графику». Использовать согласованный теоретический график целиком, без смешения его процентов с ручным фактическим остатком. Честно обозначить ограничения; фактическую историю без банковского графика не обещать.
- Когда исходных данных нет, история не занимает пустую большую карточку и не предлагает переключить режим ради её заполнения. Доступ к восстановлению исходных условий остаётся в необязательном раскрытии.
