# Ясномера — B+ Final: implementation notes

Дизайн-итерация принятого B+. Без нового аудита, изменений production или GitHub. Финальный самостоятельный файл: `yasnomera-mortgage-prototype-b-plus.html`. Открывается без сборки и внешних зависимостей. Предыдущие B и B+ локальные файлы сохранены; B+ Final обновляет основной дизайн-референс.

## Принятые решения сохраняются

Месячный обязательный платёж — главный результат на тёмно-зелёной поверхности. До первого изменения условий — «По примеру», после — «Ваш сценарий». Числовой ввод первичен; каждый ползунок непосредственно под своей суммой. Срок уточняется рядом с годами через 0–11 месяцев. Справка ЦБ рядом со ставкой ипотеки. Стоимость кредита, досрочные сценарии, динамика долга, график и методика остаются отдельными задачами. Mobile sticky содержит один платёж и возврат к результату. PNG/share видны как secondary actions. Новая/действующая ипотека, комфортный платёж, страховка и остальные возможности B+ сохраняются.

## Founder comment A: два самостоятельных действия

Порядок: **регулярная карточка → разовая секция → динамика долга → график**.

Регулярная карточка `#early`: белая/основная поверхность, заголовок «Регулярная доплата каждый месяц», сумма, пресеты, обе стратегии. Desktop: контролы слева, результат справа; mobile: контролы, затем результат. Здесь результат подписан **«Только регулярная доплата»** и не включает разовые платежи. При нулевой регулярной сумме — спокойное приглашение рассчитать её эффект, без требования заполнить блок.

Разовая секция `#one-time`: отдельный контейнер на soft surface, самостоятельный заголовок «Разовые досрочные платежи», короткое объяснение, действие «Выбрать месяц в графике», видимая форма «Месяц расчёта + Сумма доплаты», добавление и список с удалением. Форма не спрятана в регулярной карточке. Сумма формы первоначально пустая, пример — placeholder; она учитывается только после добавления. Месяц 1 означает первый месяц текущего расчёта, в том числе для действующей ипотеки.

Прямо сказано: разовые платежи можно использовать без регулярной доплаты или вместе с ней. Важно не превращать эти два типа действий во взаимоисключающие режимы: production поддерживает их сочетание.

При наличии разовых показывать результат с явной областью расчёта: **«Только разовые доплаты»** при нулевой регулярной сумме; **«Регулярные + разовые доплаты»** при сочетании. Итоговая экономия сравнивается с теми же базовыми условиями без любых досрочных, а не с регулярным сценарием. Не суммировать две показанные экономии: второй результат уже включает регулярную доплату. Динамика долга, стоимость кредита, график и PNG используют выбранный совокупный сценарий.

Выбор «Уменьшать срок / Уменьшать платёж» остаётся общим правилом стратегии; пояснение под ним говорит, что он применяется и к добавленным разовым доплатам. Не дублировать переключатель с независимым состоянием в разовой секции: это изменило бы существующую модель сценария.

## Founder comment B: срок по условиям и эффект доплат

В hero `#duration` показывать срок базовых условий, **не фактическую длину расписания после досрочных**. Для новой ипотеки подпись «Срок по условиям», для действующей — «Осталось по условиям». Эффект досрочных — «Закроете ипотеку через» и «Срок меньше на» — расположен в результатах досрочных сценариев.

Исключение, необходимое по смыслу: в режиме подбора срока по комфортному платежу и при известном платеже действующей ипотеки не называть выведенный из платежа срок договорным. Подпись **«Срок без досрочных»**. Саму verified mathematics и округление срока production сохранить.

PNG также различает срок условий и закрытие с досрочными. При наличии досрочных подпись стоимости кредита уточняет «С досрочными доплатами», чтобы изменившиеся проценты не воспринимались как базовый расчёт.

## Founder comments C–E

**C.** Крупная mobile-кнопка «Показать результат» удалена из формы, её обработчик удалён. Расчёт автоматический. Остаётся sticky «К результату»: это навигация, а не запуск вычисления. Sticky скрывается при видимом hero и при редактировании numeric/text input; после blur возвращается. Radio/checkbox/range не скрывают его. В прототипе проверены оба состояния и возврат к hero.

**D.** Справка ЦБ — две компактные строки под rate/term: `Ключевая ставка ЦБ: <значение>% · справочно` и `Это не ставка вашей ипотеки.` Без отдельной карточки, длинного disclosure или текста о реализации. В изолированном прототипе показано **«нет данных»**, актуальное число не выдумано. В production подключить существующий официальный контракт значения/даты/источника; сохранить реальную актуальность и fallback. При наличии данных короткая дата допустима в той же строке. Никакой автоподстановки ключевой ставки в ипотечный input.

**E.** Из графика убрано «Первый год уже раскрыт». Первый год действительно открыт при раскрытии графика и по переходу из разовой секции. Короткая инструкция остаётся: «Укажите разовую доплату в нужном месяце. Она добавится к регулярной, если та задана». Остальные годы свёрнуты. Переход к графику не фокусирует input и не вызывает клавиатуру заранее.

## Geometry и responsive rules

Основные tokens и базовая композиция B+ сохраняются: content max-width 1200 px, desktop inputs 420 px, gap 24 px; mobile gutters 16 px, карточки padding 20 px / radius 12 px. Main payment 56 px desktop / 42 px mobile, tabular numbers. Responsive breakpoint 760 px.

Регулярная карточка: padding 28 px desktop, 20 px mobile, две равные колонки с gap 32 px на desktop, одна колонка на mobile. Результат на accent-soft surface. Разовая секция: padding 28/20 px, radius 16/12 px, soft surface без внешней рамки/тени; отделена обычным journey gap 24/20 px. Desktop форма и список слева, итог справа; только тонкий вертикальный divider. На mobile итог ниже списка, тонкий верхний divider. Поля месяц/сумма в две колонки, Add на всю ширину; заголовок и счётчик переносить без одинокой цифры. Контейнеры сценариев различаются поверхностью и названием, без добавления множества вложенных карточек.

## Проверка и доказательства

Responsive Chrome проверка: 1440×900 и 390×844; обе темы, initial/scrolled states. Desktop снимки из QA-обёртки 0,9 приведены к 1440×900; mobile 1:1. Это проверка responsive layout, не аппаратная проверка клавиатуры на Android/iOS.

| Проверка | Результат |
|---|---|
| Ползунки, месяцы | 8,1 млн / взнос 2,45 млн / 12% / 15 лет 6 мес.; платёж 67 032 ₽ |
| Только регулярные 20 000 ₽, уменьшать срок | Экономия 3 305 720 ₽; закрытие 8 лет 10 мес.; hero остаётся 15 лет 6 мес. |
| Регулярные + разово 150 000 ₽ в месяц 1 | Итоговая экономия 3 571 132 ₽; закрытие 8 лет 5 мес.; регулярный результат не меняется |
| Только разово 150 000 ₽, регулярная сумма 0 | Экономия 738 620 ₽; закрытие 14 лет 5 мес.; подпись «Только разовые доплаты» |
| Уменьшать платёж | Регулярный и совокупный результаты различаются и имеют свои подписи; hero сохраняет срок условий |
| График desktop/mobile | Первый год открыт; редактирование месяца 1 с 150 000 до 200 000 ₽ обновляет список и результаты |
| Sticky | Один платёж, автоматическое скрытие при вводе/видимом hero, возврат к результату, без дублирующего CTA |
| Режимы | Новая/действующая, комфортный/известный платёж, страховка и сброс примера проверены |
| Share | Копирование проверено на desktop и mobile; открытие ссылки восстановило срок, регулярные и разовые платежи |
| PNG | Preview проверен на desktop и mobile; фактическое скачивание PNG проверено из standalone document, файл 1200×760 сохранён и просмотрен |
| Light/dark | Снимки initial и scrolled states обеих форм-факторов, включая mobile dark, сохранены |

В mobile QA-iframe download event не перехватывается инструментом браузера; поэтому доказательство фактического скачивания получено из самостоятельного документа, а мобильный preview проверен отдельно. Это не утверждение о поломке PNG в мобильном браузере.

PNG в этом прототипе имеет preview dialog и явное «Скачать PNG»; Blob вместо автоматического data-URL download позволил проверить реальный файл. Такой dialog — демонстрационная оболочка, **не обязательная новая production-функция**. Production экспорт можно сохранить с прежним поведением. Share имеет доступный fallback-dialog для браузеров, где clipboard недоступен.

JavaScript прошёл syntax check. annuity/simulate функции совпадают с B+; новые промежуточные результаты используют тот же demonstration engine. После взаимодействий application errors в браузерном журнале не обнаружены.

## Backlog реализации

1. **P0:** перенести visual/state structure на существующий verified production engine; получить базовый срок отдельно от фактического закрытия, вычислить явно scoped regular-only и combined results тем же engine. Не заменять математику, страховые правила или ограничения demo-функциями.
2. **P0:** подключить существующий official-data contract ЦБ и его актуальность; «нет данных» в прототипе — reference state.
3. **P0:** сохранить production PNG/share/analytics contracts, month editing и все core modes; применить новые подписи срока и области расчёта.
4. **P1:** при интеграции проверить реальные Android/iOS клавиатуры, safe-area, clipboard/download и длинные списки разовых платежей. Внешних app/account тестов этот изолированный прототип не заменяет.

Все пять founder design comments закрыты в B+ Final. Нового незакрытого design decision не требуется. Финальный комплект пригоден как визуальная и interaction-референция реализации; production integration остаётся отдельной работой.
