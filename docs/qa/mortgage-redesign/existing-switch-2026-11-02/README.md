# Действующая ипотека: переключатель и сохранение банковского остатка

02.11.2026. Base: production/main c93675f. Это follow-up PR, не опубликованная версия.

## Исправлено

Переключатель известного платежа использует тот же track-relative thumb, что страховка: track 40×20, thumb 16×16, вертикальное центрирование top 50% + translateY(-50%), left 2px / 22px, label не меньше 44×44. Native checkbox/accessible name/Space сохранены; видимый focus на label обоих переключателей. Математика и другие контролы не меняются.

Дополнительно воспроизведён и исправлен сброс банковского остатка: known-payment mode, остаток 5 300 000, смена ставки 12→13% раньше подставляла остаток по скрытой исходной модели. Теперь rate edit и new→existing navigation в этом режиме сохраняют введённый остаток. Добавлена meaningful regression для обоих переходов. В режиме исходных параметров поведение пока прежнее; его переработка — отдельное предложение.

## Метрика: подтверждённое и неизвестное

На основном домене в новом маркированном QA-визите с _ym_debug=2 начальный пример не создал calculate_success. После изменения стоимости официальный SDK вывел: `Reach goal. Counter: 110360838. Goal id: calculate_success` (2026-11-02T13:06:54.351Z, то есть 16:06:54 МСК). Это подтверждение обработки вызова SDK в браузере, не независимое доказательство записи конкретного визита в серверном отчёте. Analytics code не менялся. Чужой скриншот с нулём за неполный интервал 16:00–16:09 сам по себе не устанавливает причину.

## Оставшиеся вопросы

Синхронизация remaining/paid меняет elapsed months, но не пересчитывает текущий остаток; оценка истории смешивает ручной остаток с исходным аннуитетом и ошибочно называется «реальным прогрессом». Не заявлять, что этот PR устраняет проблему истории/понятности всей формы. Предложение: docs/mortgage-redesign-kit/EXISTING_MORTGAGE_PROPOSAL.md. До решения по форме и подтверждения конкретного тестового события в отчёте Direct не запускается.
